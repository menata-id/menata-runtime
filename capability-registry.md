# Capability Registry

> Artifact 1 of the Capability Roadmap — the single source of record for runtime capabilities.
>
> One row per capability. The registry only grows (ratchet):
> a ✅ capability must never regress — its conformance test guards it.
>
> Status: v0.38 — CAP-W06 (async action outbox: notify + CAP-I01 subscription fan-out) implemented, conformance T178–T180 | Updated: 2026-08-23
> Lifecycle governance (admission test, definition-of-done, extension architecture): `capability-lifecycle.md`
> Field type selection procedure: `benchmarks/005-field-modeling-decision-framework.md`

Seeded from: the 16-feature platform benchmark (`prototype/README.md`), Case 3 gaps P1–P6
(`prototype/go/docs/examples/README.md`), Study 1 pattern mapping
(`benchmarks/000-workflow-patterns-mapping.md`), Study 2 platform survey
(`benchmarks/001-platform-capability-survey.md`), Study 5 Portal GA survey
(`benchmarks/002-portal-ga-cross-domain-survey.md`), Study 6 accounting vertical survey
(`benchmarks/003-accounting-vertical-survey.md`), Study 7 Case 10 composition findings
(`prototype/go/docs/examples/organization-composite.md`), and Study 15 field modeling framework
(`benchmarks/005-field-modeling-decision-framework.md`).

**Status** reflects the Go prototype runtime: ✅ supported · ⚠️ partial · ❌ not yet.
**Prio** is the global implementation ordering (blank = supported or not yet prioritized).
**Proof** names the conformance verification once it exists (Study 4 formalizes these).

## Workflow / Process Orchestration (Proposed — HOLD for case evidence)

Surfaced by `benchmarks/011-metadata-workflow-orchestration-brd-benchmark.md` (Study 19),
comparing Menata Runtime against an external State/Requirement/Transition-centric comparator BRD.
Proposed as **additive layers on top of** the existing emergent model (Event+Constraint+
Permission+Action), not a first-class Workflow object replacing it — Study 19 §5.2 found real,
structural reasons to keep the emergent model (Case 7's CMMN-style flexibility, Case 10/12's
cross-Machine collaboration both depend on nothing being locked into a closed Workflow envelope).
None has portfolio-case evidence yet — registered per the "silence is not a decision" rule, HOLD
until a real case declares the need, matching `CAP-V11`'s own standing HOLD posture.

**Reframed by Study 20** (`benchmarks/012-process-model-synthesis.md`, 2026-08-22): CAP-W01–W05
are no longer five independent layers but **five compile products of one mechanism — the Process
Overlay** ("declared process, emergent execution"): a `process` block the metadata loader compiles
deterministically into existing substrate primitives (Events, guards, Constraints, Permissions,
Config, scheduler entries). No Workflow Instance table, no second engine — the runtime executes
what it executes today, at today's ~3-statements-per-transition cost profile (Study 20 §3.1); the
overlay exists for authors, graph validation, and the rendered process map. Implementation order
inverts accordingly: the loader-side compiler is the trunk; W01's cardinality counter and W03's
quorum parameter are its only engine-side leaves. Performance keystone: "write-time fan-in,
read-time O(1)" — any requirement whose truth lives on other records is maintained as a
counter/flag on the parent at write time (via the existing CAP-A08/CAP-I01 post-commit site),
never queried per-transition (Study 20 §6.3).

**B1 implemented and proven 2026-08-22** (`benchmarks/013-overlay-compiler-proof.md`, Study 21):
the compiler trunk (states/transitions/actor/auto → Events/guards/Permissions,
`internal/metadata/compile.go`, `migrations/019_process_overlay.sql`) is real and
conformance-proven (T136–T139) — a Machine declaring only a `process` block runs the identical
lifecycle, rejects identically (state/role/ownership guards), and is architecturally invisible

# Rules

1. **Ratchet** — rows are never deleted; status only moves ❌→⚠️→✅.
2. **No silent regression** — every ✅ must gain an automated proof (Study 4); until then, "manual curl" is the recorded evidence.
3. **New gaps register here first** — example YAML annotations (`[NOT YET]`) are pointers; this table is the record.
4. **Every ❌/⚠️ has a priority or a stated reason to wait.**
